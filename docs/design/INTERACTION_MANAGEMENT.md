# 课表管理与作息编辑：第二轮交互统一

日期：2026-10-11。范围是管理列表、课表编辑、作息编辑；不是全应用交互验收完成。

## 承载方式与操作契约

| 操作 | 呈现与反馈 | 提交、取消和返回 |
| --- | --- | --- |
| 选择当前课表 | 保留列表内选择 | 即时切换，不强制进入编辑 |
| 进入作息编辑 | 整行可点，末尾箭头表示进入下一层 | 使用公共页面转场；复制仍是独立图标操作 |
| 编辑名称、日期、周数和作息 | 独立表单页 | 明确保存；有修改时顶部/系统返回统一确认，无修改直接返回 |
| 新建作息表 | 底部主按钮，创建后进入表单 | 创建处理中拒绝重复提交；沿用新建未保存的清理逻辑 |
| 保存 | 公共处理中状态与操作锁 | 等待真实写入完成再返回；失败显示提示并保留当前页面 |
| 放弃编辑 | 公共短确认弹窗 | 取消或外部关闭继续编辑；明确放弃后离开 |
| 复制 | 单个名称输入的短弹窗 | 检查重名，提交中禁止重复点击与关闭，失败保留输入 |
| 分享 | 沿用格式选择底部面板 | 分享持久化内容；有未保存修改或是新表时禁用复制/分享并提示先保存 |
| 删除 | 说明影响的短确认 | 等待删除结果再退出；仍被课表使用的作息继续解释删除受阻原因 |
| 修改共享作息 | 保留现有影响预览 | 用户确认后保存；该预览用于解释影响，不能当成冗余提示移除 |

不添加新的视觉组件类型。新增 EditorActionState 统一显式操作的忙碌、失败和防重复行为，退出复用第一轮的 DiscardChangesDialog。草稿对比覆盖表单数据和自动作息配置，不包含折叠状态。

## 保存完整性修复

此前绑定作息的课表，保存分支只写共享作息或绑定关系，可能忽略同页的名称、开学日期和周数。本轮 saveTableEditor 把元数据与对应分支写入同一原子事务，共用既有撤销边界。

- 保持同一绑定：保存课表基础信息和共享作息，不覆盖本表绑定前的作息备份。
- 换绑/解绑：保存基础信息，沿用绑定快照/恢复规则，不重新映射课程；目标选择仍是选择已有作息，不同时改写目标作息。
- 使用本表作息：保存基础信息、节数与作息，沿用按时间重新映射课程的逻辑。

复制和分享读取已保存内容，避免用户误以为未提交的草稿已被复制或导出。新建取消的后台清理与路由兜底保留原实现，本轮没有承诺它们完整的跨进程恢复。

## 验证边界与后续

新增行为测试覆盖连续两次提交只写入一次、写入完成前不导航、失败后可重试、取消不当作普通失败、已取消作用域不会留下忙碌状态。

设备验收仍需：连续保存/返回、删除受阻、复制重名、修改后恢复原值再返回；中英和大字体；手机、平板横竖屏与分屏；旋转后草稿、键盘与预测性返回。当前没有 Android 设备，构建和 JVM 测试不代表这些体验已验证。新增数据库事务分支仍需设备或数据库集成测试覆盖完整保存/撤销链路。

下一轮按计划推进导入流程的步骤关系、确认、失败恢复和返回行为，之后再收敛剩余设置与整体验收。
