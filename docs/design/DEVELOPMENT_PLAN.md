## 调研收口与执行范围

资料已足够支撑后续分阶段开发，结束广泛 GitHub 搜索。已有参考覆盖公共组件/主题、可中断动效、窗口与多栏适配、背景裁切/存储、局部玻璃和性能验证。现在的主要缺口是 Classy 自身的样板、设备数据与体验反馈，而不是更多项目。

必做主线：统一 UI 与柔和色条、平板与分屏基础适配、统一动效、核心流程回归。背景仍是用户提出的候选功能；局部玻璃按已同意方向安排验证性原型，是否正式接入由兼容性、可读性与性能决定。两者不阻塞基础 UI 和平板成果交付。

只有出现具体障碍才补查资料：当前依赖缺少所需 API、窗口变化导致状态/返回无法正确衔接、图片解码/裁切存在未解决兼容问题、玻璃性能未达到目标。每次补查须形成“问题—证据—选择—验证”记录。

参考依据见 [补充调研](REFERENCE_RESEARCH.md)：已有材料足够启动基线和样板页；后续按动效、适配与材质的具体问题定点补查。

## 目标与工作方式

按「简洁、美观、统一、成一套完整的体系」推进：轻纸感现代极简 + 柔和色条 + 克制跟手的动效 + 可选局部玻璃。具体规则以 [设计体系](DESIGN_SYSTEM.md) 为准。

只在 `E:/C015/classy` 单一开发目录顺序推进，沿用当前 main 工作进度。先完成一轮可安装、可比较的结果，再扩大覆盖面。每轮使用相同演示课表、主题和设备设置比较前后效果；反馈记录为具体页面和操作的问题，公共规则的修改同步检查所有使用方。

首轮改动已保存为本地基线提交 `a38115e`。后续样板单独提交，保持清楚的回退边界。遇到合并冲突先讨论。正式版本号、tag 和 Release 按实际发版请求处理，现有 v0.0.9 保持不变。

## P0：先建立可比较的起点

固定演示数据包括长课名、长地点、课程冲突、单节/连堂、空课表、节假日与已结束课程；另保留足量课程测试滚动。截图使用同一日期/周次，避免状态变化被误当作视觉差异。

问题表字段：页面或组件、操作步骤、实际表现、目标表现、严重程度、公共入口、验证方法。优先解决读不清/点不到/被遮挡，再处理风格不一致，最后处理装饰细节。

记录设备型号、Android 版本、刷新率、字体缩放、主题、动画缩放与应用构建类型。先复核已有色条修改，不反复扩大改动后才比较。

## P1：共用基础与两类样板

- 以 `ui/theme/Theme.kt`、`GlasenseColorBridge.kt` 和 glasense-ui 的 `Colors/Type/Specs` 为现有基础，明确各自职责。复用与映射已有参数，避免再建一套互相竞争的主题。
- 定义页面、普通卡片、浮层三种表面关系；主/次文字、主题操作色、课程识别色、错误色分工明确。轻纸感不等于所有页面偏黄，也不改变用户保存的主题颜色。
- 统一常用页边距、行间距、圆角类别和点击区域；通过字体层级表达主次。交互目标通常至少 48dp，密集课表按实际命中区域单独评估。
- 今日页作为内容样板，通用设置页作为表单样板；复用 `SettingsCards.kt`、`NoRippleClickable.kt` 等公共入口。
- 色条保留；68% 混色和 3dp 宽度作为当前候选值，实测后统一微调。检查自动色、自定义色、无彩色以及已结束课程，不通过继续叠加透明度来掩盖问题。
- 复用已有 `ControlGalleryScreen.kt`（先核对其覆盖与调试入口）展示共用组件，避免为样板引入生产导航入口。

体验重点：是否耐看、哪些信息最先被看到、同类控件是否像同一个应用。先稳定这两类样板，再迁移其余页面。

## P2：按使用链路推广

执行顺序：

1. 课表网格和周列表：课名/时间/地点层级、选中与冲突状态、色条、空态、周切换；保留用户已有密度与填充模式选择。
2. 课表管理与「我的」：分组、统计、入口、主次操作、空态；不重新加入重复管理入口。
3. 课程详情与新增/编辑：标签、输入框、保存/取消、错误反馈；检查键盘与底部操作区。
4. 导入和作息编辑：选择、预览、确认、草稿恢复；复核 ImportSheet 安全区，防止重新出现向上窜动。
5. 外观、提醒、小组件、关于等其余子页与弹窗：逐一登记完成状态，收敛按钮、标题、分隔线、表面和中英文排版。
6. 桌面组件：课程颜色语义、文字层级与变淡规则和 App 保持一致；遵守 RemoteViews 能力边界，单独确认对比度，不机械照搬 App 的玻璃或透明度。

UI 改造保持数据与导入规则稳定；若发现必须改变业务行为的设计问题，单独记录问题与方案再确定范围。

## P3：统一动效的职责与节奏

审查入口：`SleepyMotion.kt`、`SleepyMaterialTransition.kt`、`PillNavigationBar.kt`、`SegmentedSwitcher.kt`、公共按压与弹层组件。

- 为每类动效登记触发、空间方向、曲线来源、结束状态、打断行为、减少动态效果行为；业务页只选择语义，不各自随意写一套参数。
- 点按即时回应；底栏与分段选择只有一个主要选中反馈。指示器从当前位置追随新目标，页面内容不逐项飞入。
- 二级导航进入/返回成对，专门比较当前 0.92 页面缩放的阅读影响；保留 Navigation3 预测性返回能力。先对比录屏再确定最终幅度，不预先套参考项目数值。
- 弹层与键盘协同：安全区只有一个最终负责人；展开和关闭均可中断，不残留遮罩或不可点击层。
- 拖动跟手，落位有明确反馈；保存、撤销与删除结果不依赖动画完成回调来保证正确性。
- 静止页面无装饰性循环；尊重系统关闭动画，检查自定义动画是否绕过系统设置。

必须操作：连续快速切 tab、动画中返回再进入、预测性返回取消/完成、连续开关弹层、键盘展开时返回、拖动取消/落位/撤销、转屏及后台恢复。功能正常并不代表动画已流畅，需要录屏和设备帧数据。

## B：候选背景功能

实施细节见 [自定义背景方案](CUSTOM_BACKGROUND.md) 与 [Chrnova 评估](CHRNOVA_BACKGROUND_REVIEW.md)。采用克制的裁切交互：拖动、双指缩放、显式重置、操作时辅助线；应用前带真实课程预览。保存源副本和归一化焦点，适应平板/分屏；确认后写入持久目录，失败保留旧图。

背景与课程颜色独立。首版以可读默认值与一个柔化调节为主，不引入视频、视差或多套无限制透明度参数。额外高级控制只有在体验验证出明确需求后才增加。按静态图、复杂纹理、超大照片、重启恢复、清理缓存、取消/替换失败和窗口变化逐项验收。

## P4：玻璃的有限试点

优先核对 Backdrop 与当前 Kotlin/Compose/minSdk 的兼容版本，再比较是否需要 Haze；同一原型不同时引入两套渲染管线。锁定依赖与许可记录。

只改 Dock 材质，保持布局、选中态、触摸命中与导航逻辑。默认实色；可选玻璃；不支持时同布局实色降级。用一个公共材质入口处理采样、模糊、折射和底色，文字保持清晰。首轮不扩展到菜单和课程卡。

性能验收采用可重复的同设备、同数据、非调试构建对照：切 tab、滚动课表、打开/关闭编辑页，每场景预热后至少三次测量。记录 P95 帧时间、错过帧截止时间的比例、内存及稳定后是否还在持续渲染。60Hz/120Hz 的帧预算分别约 16.7/8.3ms，不能仅靠平均 FPS 判断。

候选接入门槛：玻璃开启后 P95 帧时间与内存相对实色增幅各不超过 10%，卡顿帧比例增加不超过 1 个百分点；底层若已有明显卡顿，应先修复，不能因相对变化小就判定合格。阈值属于本计划的初始工程目标，非已达成结果，需在选定设备上记录绝对值和重复测量波动。

同时满足：明暗壁纸可读、无自采样伪影、无持续空转、返回无残影、无布局跳动、低版本回退正确。达不到则继续实色交付，记录阻碍，不降低文字可读性换效果。

## 每轮验收与交付规则

| 维度 | 覆盖要求 |
| --- | --- |
| 主题与色彩 | 明暗主题、默认/自定义主题、自动/自定义课程色、无彩色、色条/填充、已结束课程 |
| 语言与空间 | 简体中文/English；窄屏、横屏；默认字体与 1.3/1.5 倍字体；屏幕边缘与键盘安全区 |
| 可访问性 | 阅读对比度、非颜色提示、点击目标、TalkBack 顺序；普通正文目标 4.5:1，大字目标 3:1，装饰色条不套用正文指标 |
| 核心任务 | 看课表 → 切周 → 详情 → 编辑/保存 → 返回；新增/拖动/撤销；导入/确认/恢复草稿；切课表；设置与小组件 |
| 设备 | 至少一台实际常用 Android 手机及一台真实 Android 平板；模拟器补足窗口边界；动效/玻璃补充性能较弱或较低 Android 版本设备；可用时覆盖 60/120Hz；未覆盖列为待验收 |
| 工程验证 | 每轮先跑受影响测试与编译；里程碑跑完整 JVM 测试、Lint、APK 构建。状态/返回行为新增有意义测试，纯间距修改不新增字符串匹配测试 |

每轮交付简短改动说明、截图/录屏、安装包、测试结果及待验收项。调试包和正式包标明身份；若需要覆盖原正式版数据体验，使用既有签名并检查版本策略。正式发版前再更新版本号与匹配的中英更新说明。
